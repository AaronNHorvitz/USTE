# Decision 0129 — Encrypted packed index pages

Date: 2026-09-19

Status: accepted and locally verified T-20 framing carrier; index integration open.

Decision 0128 separates canonical logical content from physical layout. The next carrier packs
small immutable records into fixed pages, avoiding one encrypted object per Patricia node. This
decision defines framing only, not the node/value payload grammar, root authority, publication,
copy-on-write algorithm, cache admission or a graph profile. No existing v1 reader or M1 path uses
this format. A decoded page is not a canonical tree or an authorized database handle.

`packed-index-page-v2` uses 16,384 plaintext bytes. Integers are unsigned big endian. Header:
magic `UICP` (0..4), major 2 (4), minor 0 (5), nonzero family (6), zero (7), nonzero creation
revision u64 (8), zero-based page u64 (16), record count u16 (24), used bytes u16 (26), four
reserved zeros (28), index profile (32..64), fresh nonzero opaque pack object ID (64..80).
The page number is less than 16,777,216. Creation revision belongs to the immutable pack, not
the revision of every future root referencing it.

A fixed 128-entry directory follows at byte 80; each slot is offset u16 then length u16. There
are 1..128 records. Active entries describe contiguous, nonoverlapping records beginning at
byte 592 and ending exactly at `used`; unused directory entries and remaining page bytes are
zero. Each record contains a one-byte kind (1: tree node, 2: value chunk), followed by nonempty
payload. Other kinds are rejected. Maximum payload is 15,791 bytes. These are opaque framing
classes: subsequent typed payload validation is mandatory before traversal or value release.
There is no ordering requirement between slots; links use exact object/page/slot identities.

Encrypt with the unchanged crypto-v1 envelope, role IndexPage, object-format major 2/minor 0,
4 KiB frames, exact database/namespace/epoch/writer, pack ID and sequence `page + 1`.
Encoded size is exactly 20,545 bytes. The new object-format context separates the key/AAD domain
from index-v1 even if an object ID is accidentally reused. Revision/profile/family are verified
inside authenticated plaintext before exposing a record. Pack IDs must be freshly generated by
the eventual storage writer; the framing constructor validates nonzero identity, not freshness.

Builders use one fallibly allocated fixed-size zeroizing plaintext buffer. A rejected append
leaves all existing records unchanged. Empty builders cannot be sealed. Decode rejects ciphertext
length before envelope allocation, then authenticates, checks all header bindings, the entire
directory, record kinds and padding before returning any borrowed record. No untrusted count
drives allocation. Decrypted buffers use the existing zeroizing SecretBytes owner. No debug
surface exposes keys, payloads, profiles or content hashes. Existing key-vault lock, entropy,
nonce-session and error semantics remain unchanged.

Required tests cover exact capacity, atomic refusal, every truncation and trailing byte, each
authenticated header/context substitution, malformed directory/padding/kind, fixed-size encrypted
round trips, locked vault and entropy failures. This framing increment does not write a filesystem,
publish roots, survive a process loss by itself, or qualify BM-01/BM-06. Those remain integration
and recovery work; T-35 retains ownership of authoritative compaction and orphan reclamation.
