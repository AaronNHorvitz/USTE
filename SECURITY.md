# Security policy

## Current status

USTE has no released or supported executable version. Local implementation and tests may be in
progress, but neither documentation nor a development build is a security audit, certification
or deployment recommendation. Do not use it to store sensitive production data.

## Reporting readiness

A private vulnerability-reporting channel has not been established or verified.
No email address, response SLA, bounty program or supported-version promise is asserted.
Task T-62 must enable and test the selected GitHub private vulnerability-reporting route before
any executable alpha, beta, release candidate or release is distributed. Local engine
implementation does not depend on that owner-administered operation.

The intended private discussion includes the reporter and the repository participants
authorized to administer or collaborate on the security report, including applicable owners,
administrators and security managers. It is not accurately described as maintainer-only.

Until then, public issues may discuss non-sensitive design concerns. Do not post credentials,
private files, personal data, or exploit details that could harm another project. A public
issue may request a private contact without disclosing sensitive details.

## Planned release policy

Before executable distribution, verify the private reporting procedure and triage ownership.
Before releases, document supported
versions, update distribution, coordinated disclosure and advisory practices. Version support
must match actual maintainer capacity. No automatic commitment to a fixed response time.

Threat model and implementation obligations: [security and privacy](docs/security-and-privacy.md).
Testing obligations: [verification](docs/verification-and-benchmarks.md).
